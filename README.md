# 当直ノート

2026年4月入職の成人系メンバー向けの当直表Webアプリです。
Python / FastAPI / SQLite / OR-Toolsを使用し、画面はビルド不要のHTML・CSS・JavaScriptで実装しています。
データはブラウザーではなくPythonサーバーのDBに保存します。

対象期間は2026年4月〜2028年3月で、施設固有の研修条件を実装しています。
メンバー・研修期間の登録、自動生成、手動の移動・交換、月別集計、複数案の管理、PDF出力に対応しています。
DB本体や実際のメンバー情報はリポジトリに含めず、初回起動時に空のDBを作成します。

## 動作環境

- Python 3.12以上
- モダンブラウザー（PC・スマートフォン）
- Node.js 18以上（フロントエンドのテストを実行する場合のみ）

画面のビルドやNode.jsのパッケージインストールは不要です。
`requirements.txt` は直接依存するライブラリの範囲指定、`requirements-lock.txt` はWindowsのPython 3.12環境で検証した依存バージョンです。

## 起動

### Ubuntuで直接起動（WSLを使用しない場合）

Python 3.12以上が必要です。Ubuntuのターミナルで必要なパッケージを準備し、バージョンを確認します。

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
python3 --version
```

表示が3.12未満の場合は、Python 3.12以上と対応するvenvを用意してから進めてください。以下の `python3` には、そのPythonを使用します。

リポジトリを取得し、`requirements.txt` があるディレクトリで初回の環境を作成します。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

ブラウザーで [http://localhost:8765](http://localhost:8765) を開きます。停止はCtrl+Cです。
2回目以降は、同じディレクトリで次のコマンドだけを実行します。

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

同じLANのスマホから接続する場合は、代わりに次のコマンドで起動します。

```bash
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8765
```

スマホで `http://UbuntuのLAN側IPアドレス:8765` にアクセスしてください。ファイアウォールを使用している場合は、信頼できるLANからの接続を許可します。認証は未実装のため、アクセスを制限したネットワークで使用してください。
開発中にPythonコードの変更を自動反映する場合は、起動コマンドの末尾に `--reload --reload-dir app` を追加します。

### WSLでの起動

リポジトリを取得し、`requirements.txt` があるディレクトリで実行します。
初回はWSL側にPython 3.12以上の仮想環境を用意してください。

```bash
python3 --version
python3 -m venv ~/.venvs/duty-planner
~/.venvs/duty-planner/bin/python -m pip install --upgrade pip
~/.venvs/duty-planner/bin/python -m pip install -r requirements.txt
bash run-wsl.sh
```

ブラウザーで [http://localhost:8765](http://localhost:8765) を開きます。2回目以降は `bash run-wsl.sh` だけで起動できます。
`~/.venvs/duty-planner` のPythonを使用し、Pythonコードの変更を自動で再読み込みします。
別の仮想環境を使う場合は `DUTY_PYTHON=/path/to/venv/bin/python bash run-wsl.sh` で指定できます。Windows側で作成した仮想環境はWSL側で流用しないでください。
停止はCtrl+C。別ポートを使用するときは `bash run-wsl.sh 8787` とし、ブラウザーも [http://localhost:8787](http://localhost:8787) に変更します。

画面だけ更新され、削除で「Method Not Allowed」や期間重複の拒否が出る場合は旧Pythonサーバーに接続しています。古い起動プロセスをCtrl+Cで止め、上のコマンドで起動し直してください。Windows版とWSL版を同じポートで同時に起動しないでください。`/api/bootstrap` に `"api_version":3` があれば更新済みサーバーです。

### Windows PowerShellでの起動

Python 3.12以上を使用します。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\run.ps1
```

ブラウザーで [http://localhost:8765](http://localhost:8765) を開きます。
起動したターミナルの Ctrl+C で停止します。

同じWi-Fiのスマホから使用する場合:

```powershell
.\run.ps1 -Lan
```

スマホで `http://PCのLAN側IPアドレス:8765` にアクセスします。必要に応じてWindowsのプライベートネットワーク用ファイアウォールで当該ポートへの接続を許可します。
認証は未実装なので、初期版は個人PCまたはアクセスを制限した院内環境向けです。インターネット公開時は認証・HTTPSを備えた運用構成にしてください。
WSLの起動スクリプトも `0.0.0.0` で待ち受けます。スマホからの接続には、WSLのネットワーク設定によって追加設定が必要です。

## 使い方

1. メンバーの氏名、当直対象期間、研修期間を登録します。
2. 必要ならホームで病院独自の休日を追加します。土日・日本の祝日は自動判定です。
3. 開始日・終了日を指定して当直表を作成します。同じ期間の複数案も作成できます。案は番号で区別し、回数・連続勤務・間隔は他の案と合算しません。
4. カレンダーの「＋ 2枠目」で必要な2名配置を指定します。
5. 「自動生成」を押します。明示的に「固定」した担当者を維持し、それ以外は作り直します。手動で担当者を指定しただけの枠も再生成の対象です。
6. 担当者をタップして変更、固定、解除、移動・交換を選びます。PCではドラッグ＆ドロップ、スマホでは長押しで移動元を選択できます。
7. 横スクロール／スワイプ、または左右ボタンで月を切り替えます。集計は選択中の暦月について即時更新されます。
   麻酔科研修者がいる月は、下部の「麻酔科の内訳」で平日当直2回・休日系2回・金曜当直1回の目安に対する回数と達成状況を表示します。期間内だけを集計し、未達を警告しますが保存・確定は妨げません。金曜当直の重複計上は自動生成と同じ基準です。
8. 条件・未割り当て・勤務間隔を確認して確定し、PDFを出力します。

下書きもDBへ自動保存します。「取り消し」は直前の当直表操作を戻します。研修・メンバーの変更は取り消しの対象外です。
確定表を変更するときは「編集を再開」を使用します。
不要な案はカレンダー上部の「当直表を削除」から削除できます。確認後、その案の枠・割り当て・履歴を削除します。メンバー登録と他の案は残ります。

休日も不要な日直・当直枠を無効化できます。未割り当ての枠を選び、「この枠を無効にする」を押してください。担当者がいる場合は先に割り当てを解除し、2枠ある場合は2枠目から無効化します。「＋枠」で再び有効にできます。無効な枠は自動生成・未割り当て警告の対象外です。

## 割り当て条件

必須・優先条件の一覧はホーム画面と `app/rules.py` にあります。
同じ判定関数を自動生成の最終検証と手動変更の検証に使います。

- 全期間で「当直」に名称を統一。日直と当直は別勤務です。
- 1年目は月4回の上限を外し、有効な枠をすべて埋めるように配置します。2年目（2027年4月以降）は月4回ちょうどです。必須回数は1か月全体を含む表で、その月に当直対象期間がある非アーカイブのメンバーに適用します。2年目の月の一部だけの表は月4回までです。研修や対象期間・枠数の制約で4回を組めない場合は理由を表示し、元の表を保持します。
- 当直表の開始から各月までの合計回数を最優先で公平に配分し、次に月ごとの合計、平日当直・休日日直・休日当直の累計を対象日数に応じて均等にします。過去の月の割当を引き継いで次月の偏りを補正し、画面で全期間の累計を確認できます。将来の退職予定に応じて前倒しで勤務を増やしません。
- 精神科月曜、新阿武山病院平日・研修日前夜、土曜カウンセリング、へき地研修を制限します。
- 研修科に応じて配属先を限定します。麻酔科・外来研修は「院内」、精神科は「院内／新阿武山病院」、地域研修は「高槻病院近傍／へき地」です。「へき地」は地域研修の配属先として登録し、期間中の日直・当直を禁止します。旧形式のへき地研修データは起動時に移行します。
- 新阿武山の通常研修日は平日（休日を除く）。「追加研修日」「研修なし」で例外を指定できます。
- 麻酔科は平日当直2回・休日系2回・金曜1回を優先条件として扱います。金曜当直は両方の内訳へ数え、実勤務合計は1回です。
- 同日の複数勤務は禁止。当直の翌日は日直・当直とも不可ですが、日直の翌日は日直・当直とも可能です。許可される連日勤務も含め、短い勤務間隔にはペナルティを与えて可能な限り間隔を空けます。
- 土日祝は各日の日直・当直各1枠を初期設定します。不要な枠は手動で無効化でき、自動生成でも無効のまま維持します。2枠目は指定時だけ作成します。
- 土日祝を最優先して配置します。月〜金は祝日を含め原則週3日までとし、週3日を埋める最低日数の制約は設けません。平日の空きを許容し、不要な自動枠は無効にします。手動で指定した追加枠・固定勤務・無効化は維持します。
- 合計回数と平日当直・休日日直・休日当直それぞれの回数を、在籍期間と研修条件の範囲でできるだけ均等にします。
- 回数上限・公平性・当直翌日の勤務禁止・間隔は、同じ案の中だけで判定します。同じ案の月境界は連続して評価しますが、別案との連続性は評価しません。
- 希望休、外科副直、振休管理、他年度・小児科の配置、通常業務を含む法定休日判定は対象外です。

## 自動生成の方法と限界

OR-Tools CP-SATで月ごとに順に最適化します。休日未充足、全枠の未充足、合計回数の偏り、区分別回数の偏りの順に最小化します。それぞれの結果を悪化させず、最後に勤務間隔・研修の優先条件を調整します。
週が月をまたぐ場合は前月の選択日と後月に残る日数を考慮します。
固定・指定枠を維持し、未割り当てのある案も下書き保存できます。1年目の有効枠に未割り当てがある表は確定できません。2年目は月4回の条件を満たせば空き枠があっても確定できます。自動配置で無効になった平日の空き枠は、確定を妨げません。1年目は有効な平日枠を維持します。勤務禁止条件などで充足できない枠は未割当として表示します。自動配置は原則週3日までの範囲で、2年目の月4回に必要な平日枠を有効にします（指定した追加勤務、週4日以上の祝日は例外）。2年目の月全体の表は、4回未満でも下書きを編集できますが、対象者全員が4回になるまで確定できません。

最適化には時間制限があり、長期間を一括した数学的な最適解を保証しません。固定条件の矛盾と時間切れで案が見つからない状態を区別し、既存の表を壊さず返します。実行状態・乱数シード・入力条件をDBへ記録します。
学年・研修の境界や短い対象期間では、研修別の内訳目標などの優先条件が満たされない場合があります。

## 保存・DB設計

初期DBは `data/duty.sqlite3`。環境変数 `DUTY_DB` で変更できます。
バックアップはサーバー停止後にこのファイルをコピーしてください。
DBには氏名・研修日程・当直表・操作履歴が含まれるため、Gitへの登録対象から除外しています。
`.env` ファイルの自動読み込みは実装していません。環境変数は起動するシェルで設定してください。

| テーブル | 保存内容 |
|---|---|
| members | 氏名、表示色、生成対象からの非表示状態 |
| eligibility | メンバーの当直対象期間（複数可） |
| rotations | 研修科・配属先・期間 |
| training_events | カウンセリング日・新阿武山の研修例外日 |
| holidays | 病院独自の休日 |
| plans | 対象期間、下書き／確定、楽観ロック用version |
| slots | 日付、日直／当直、枠番号、有効状態、自動／手動の設定元 |
| assignments | 担当者、固定状態、自動／手動の割り当て元 |
| history | 操作前の表・メンバー・休日のスナップショット。取り消し・確定版PDF用 |
| generation_runs | 生成時の条件、状態、乱数シード |

1枠1担当者、同日同種の枠番号の一意性、外部キーをDBでも制約します。
SQLiteトランザクションにより、交換時の片側だけの保存を防止します。
versionを使い、複数端末からの古い状態による上書きを拒否します。生成中にメンバーや同じ案が変わった場合も保存を止めます。別案の編集は干渉しません。
回数集計は割り当てから毎回算出します。初期スキーマは `app/db.py` にあります。

## メンバー情報の一括登録

`scripts/import_members.py` で、非公開JSONから当直対象期間・研修期間・研修日を一括登録できます。入力ファイルはGit除外対象の `data/import/` に置いてください。
登録先サーバーのアプリを停止し、リポジトリのルートで実行します。

```bash
# 確認のみ（保存しません）
.venv/bin/python scripts/import_members.py data/import/rotation_members.json

# 内容を確認して登録
.venv/bin/python scripts/import_members.py data/import/rotation_members.json --apply
```

通常と異なるDBを使っている場合は、起動時と同じ `DUTY_DB` を設定するか `--db /path/to/duty.sqlite3` を指定してください。対象DBが存在しない場合は中止します。

- JSONの `members` 配列に、メンバー登録APIと同じ形式で `name`、`periods`、`rotations`、`events` を指定します。
- 氏名一致で既存メンバーを更新します。`surname_only: true` の場合は、空白を除いた氏名の先頭が姓に一致する人を検索します。必ず確認表示で対応を確認してください。
- 候補が複数なら中止します。必要なら入力レコードの `member_id` で対象IDを明示できます。該当者がなければ新規登録します。
- 更新対象の当直対象期間・研修期間・研修日は、入力内容で全置換します。既存の氏名・色・非表示状態は維持します。入力に含まれないメンバーは変更しません。
- 登録前にDBの隣の `backups/` にバックアップを作成します。全員を一つのトランザクションで登録し、既存の当直表に必須条件違反が生じる場合は全件取り消します。
- 同じデータを再実行してもメンバーや研修期間は重複しません。登録後はアプリを再起動し、画面を再読み込みしてください。

## GitHubへの登録とデータの除外

`.gitignore` は次を除外します。

- DB本体とSQLiteの補助ファイル（`*.db`、`*.sqlite`、`*.sqlite3`、各形式のWAL・SHMなど）
- 運用データ・生成物のディレクトリ（`data/`、`tmp/`、`output/`、`outputs/`、`exports/`、`backups/`）
- 出力PDF、CSV・TSV・Excel、ログ、バックアップファイル
- `.env` などのローカル設定、秘密鍵、認証情報ファイル
- 仮想環境、Pythonキャッシュ、エディター設定

DBを作成するソースコード（`app/db.py`）は含めます。テスト・検証用スクリプト内のデータは架空のもので、実際のメンバー情報には置き換えないでください。
実データを含むスクリーンショットや別名の設定ファイルは拡張子だけで判別できないため、追加する前に内容を確認してください。
`.gitattributes` でシェルスクリプトをLF改行に統一し、Windowsで取得したファイルもWSLで実行できるようにしています。

初回登録時はリポジトリのルートで次を実行し、コミット対象に実データがないことを確認します。

```bash
git status --short --ignored
git add .
git diff --cached --stat
git diff --cached --name-only
git diff --cached
```

`.gitignore` は既に追跡されているファイルや過去のコミットには適用されません。既存リポジトリに追加する場合は、追跡対象と履歴も確認してください。

## 休日を平日として扱う

ホーム画面の「休日を平日扱いにする」から日付を登録できます。土日、日本の祝日、病院独自の休日より優先され、全ての当直表に適用されます。「解除」で元の休日設定に戻せます。

平日扱いの日は日直枠を無効にし、既存の当直枠は維持します。自動配置、平日当直の月別・全期間集計、研修日の判定にも反映します。日直に担当者が入っている場合は、先に割り当てを解除してください。その日または前日を含む確定表がある場合は、編集を再開してから変更します。条件に違反する既存勤務がある場合は変更を保存せず、理由を表示します。


### 全期間の合計回数の保証

自動生成では、月ごとの最適化後に全月をまとめて検証します。全員の当直対象日数が同じ場合は合計回数の差を1回以内に制限します。対象日数が異なる場合は、全割当回数を対象日数に比例配分し、その切り捨て〜切り上げの範囲を各人の必須回数とします。

偏りが残る場合は最大30秒の全期間調整を行い、有効枠・配置済み枠数・固定担当者・研修条件・当直翌日の勤務禁止・2年目の月4回を維持して再配分します。条件を満たせない場合や時間内に確認できない場合は理由を表示し、元の表を保持します。公平性は自動生成時の保証であり、その後の手動編集によって回数は変わります。


### 自動生成の進捗表示

探索中の待ち画面には、対象月、現在の処理（休日枠の充足、合計回数・勤務種別・勤務間隔の調整、全期間の公平性検証、保存）、完了した月数、経過時間、処理履歴を表示します。探索中に見つかった候補案の件数も逐次更新します。候補数は現在の探索段階で確認した数で、配置済み人数や最適解の保証を表すものではありません。

進捗は `POST /api/plans/{id}/generate-stream` のストリーミング応答で受信します。月数のバーは月別配置の完了数であり、その後に全期間の公平性検証・保存を行います。既存の通常生成APIも引き続き利用できます。途中でエラーになった場合は理由を表示し、通信が切れた場合は画面を再読み込みして保存状態を確認してください。

## 自動配置アルゴリズム

### 全体の構成

自動配置には Google OR-Tools の CP-SAT ソルバーを使用しています。各勤務枠に誰を割り当てるかを0・1の変数で表し、必須条件を満たす組合せの中から、未割当・回数の偏り・勤務間隔の短さなどを減らす案を探索します。

処理は「月単位の配置」「全期間の合計回数の保証」「検証・保存」の3段階です。全ての勤務条件と優先条件を最初から全月一括で最適化する方式ではありません。同じ期間に複数の当直表があっても、別の表の割当は合算しません。

### 1. 対象者と勤務枠の準備

- 登録された当直対象期間と研修条件から、各枠に配置できるメンバーを決めます。アーカイブ済みのメンバーは原則として新規配置の対象外ですが、この表に固定勤務がある場合は、その固定勤務を保持するために扱います。
- 土日・日本の祝日・独自休日を休日として判定し、「平日扱い」の指定があれば優先します。この判定は勤務種別の集計と研修条件の判定にも共通です。
- 固定担当者を維持し、固定されていない担当者は再配置の対象にします。
- 1年目は既存の有効枠を維持し、月4回の上限を設けず充足を優先します。手動追加や休日登録で週3日を超えた有効枠も維持します。
- 2年目は、固定されていない自動設定の平日当直1枠目について、有効・無効も探索します。月〜金の当直は祝日を含め原則週3日までですが、手動指定枠・固定勤務などの維持を優先します。

### 2. 月単位の配置と優先順位

開始月から順に配置します。既に配置した過去の月と、将来の月にある固定勤務を考慮し、月境界の勤務禁止条件や勤務間隔も確認します。

主な必須条件は、1枠1名、同じ人の同日複数勤務の禁止、当直翌日の日直・当直の禁止、当直対象期間・研修条件の遵守、固定勤務の維持です。日直翌日の勤務は可能です。2年目は月4回を上限とし、表が暦月全体を含む場合は、その月に当直対象期間のある非アーカイブのメンバー全員を4回ちょうどに配置します。月の一部だけの表では4回未満を許容します。

月内の探索では、次の順序で目的関数を最小化します。

| 順序 | 評価内容 |
| --- | --- |
| 1 | 有効な休日枠の未割当数 |
| 2 | 全ての有効枠の未割当数 |
| 3 | 当直表の開始から現在の月までの合計回数の偏り |
| 4 | 現在の月の合計回数の偏り |
| 5 | 開始から現在の月までの、平日当直・休日日直・休日当直の回数の偏り |
| 6 | 現在の月の、上記3種別の回数の偏り |
| 7 | 勤務間隔、研修中の配置希望、自動平日枠の使用などのペナルティ |

ある段階で案が見つかったら、その評価値を悪化させない制約を追加して次の段階に進みます。ただし、時間制限があるため、各段階で数学的な最適値まで到達するとは限りません。

回数の偏りは、対象期間中の当直対象日数に比例した配分との差で評価します。メンバーの回数を `c_i`、対象日数の比を `w_i`、総回数を `C`、対象日数の比の合計を `W` とすると、`|c_i × W - C × w_i|` の合計を小さくします。月内の評価にはその月の対象日数、累計の評価には表の開始から現在の月末までの対象日数を使います。研修による勤務不可日は、対象日数の重みから差し引かず、配置できるかどうかの必須条件として扱います。

勤務間隔の評価では、1〜7日差の勤務にペナルティを付け、短い間隔ほど重くします。麻酔科研修中の勤務内訳や、外来・地域・新阿武山病院研修中の休日系勤務の優先なども、この最後の段階で評価します。これらは可能な範囲で改善する優先条件です。

### 3. 全期間の合計回数を必須条件として保証

月ごとの探索だけでは、各月で3〜4回に収まっていても、累計で6回と8回の人が生じる場合があります。そのため、全月の配置後に合計回数を必ず検証します。

全期間の割当済み有効枠数を `T`、メンバー `i` の全期間の当直対象日数を `d_i`、対象日数の合計を `D` とし、各メンバーの合計回数を次の範囲に制限します。

```text
下限 = floor(T × d_i / D)
上限 = ceil(T × d_i / D)
下限 ≤ メンバーiの全期間の合計回数 ≤ 上限
```

対象日数が同じメンバー同士では、合計回数の差は必ず1回以内になります。例えば66枠を同じ対象日数の9名に配分する場合は、7回が6名、8回が3名です。未割当枠は `T` に含みません。

範囲を外れる人がいる場合は、全月をまとめた別のCP-SATモデルで担当者を再配分します。この調整では以下を守ります。

- 有効・無効の設定と、どの枠が割当済み・未割当かを変更しない。
- 固定担当者、当直対象期間、研修条件、同日複数勤務の禁止、当直翌日の勤務禁止を維持する。
- 2年目の月4回の条件を維持する。
- 合計回数の上下限を必須条件とし、その範囲内で担当者の変更件数を最小化する。

この最終調整は合計回数の公平性を保証するためのものです。月別回数や勤務種別、勤務間隔の評価値をそのまま固定するものではなく、それらは調整前から変化する場合があります。勤務種別ごとの回数差1回以内や、全ての優先条件の大域的な最適性は保証していません。

公平性の範囲を満たす案が得られない場合は、制約を緩めた案を黙って採用せず、エラーとして終了します。この判定は、月単位の探索で選択した枠と充足状況を維持した条件での結果です。別の枠設定でも配置不可能であることまで意味するものではありません。

### 4. 探索時間と結果の扱い

現在の探索時間設定は次のとおりです。

| 処理 | 1回の探索時間上限 |
| --- | --- |
| 休日枠の充足、全有効枠の充足 | 各3秒 |
| 累計合計、月内合計、累計勤務種別、月内勤務種別の調整 | 各4秒 |
| 勤務間隔・研修の希望条件などの調整 | 7秒 |
| 必要な場合の全期間の合計回数の再調整 | 30秒 |

月内の探索上限の合計は29秒で、これにモデル構築・検証・保存などの時間が加わります。上限より早く終了することもあります。探索は4ワーカーで行い、生成ごとの乱数シードを保存します。シードや並列探索の進行状況によって結果は変わり得るため、同じシードでも完全な再現性を保証するものではありません。

`OPTIMAL` はその探索段階の最適性を確認できた状態、`FEASIBLE` は必須条件を満たす案が得られた状態です。初期の充足探索で案が見つからなければ生成を中止します。その後の月内の改善探索で案が見つからない場合は、それまでに得た案を保持して次へ進みますが、保存前の全期間の公平性検証は省略しません。

「時間内に配置案が見つかりませんでした」は、時間内に実行可能な案を確認できなかったことを示し、配置不可能と証明された状態とは区別します。全期間の公平性を確認できない場合も、偏りのある案は保存しません。

### 5. 進捗配信・最終検証・保存

探索段階の開始・終了や候補案の発見をコールバックで通知し、進捗APIから画面へ逐次配信します。月ごとの完了数が全月に達した後も、全期間の公平性検証・必要な再調整・最終検証・保存を行います。進捗バーは月別配置の完了数を表し、探索全体の残り時間を推定するものではありません。

保存前に勤務条件と2年目の必須回数を共通の検証処理で再確認します。保存時には表のバージョンを再確認して他の編集との競合を防ぎ、直前の状態を履歴に残してから、割当と生成履歴を1つのトランザクションで保存します。生成に失敗した場合は、保存済みの表を保持します。自動生成後の手動編集によって公平性の回数範囲を外れることはあるため、編集後は集計を確認してください。

主な実装箇所は、月単位の探索を行う `app/solver.py` の `generate()`、合計回数の範囲を算出する `fairness_bounds()`、全期間を検証・調整する `enforce_plan_fairness()`、共通条件・集計を定義する `app/rules.py`、進捗配信と保存を行う `app/main.py` の `generate_stream()`・`run_generation()` です。
